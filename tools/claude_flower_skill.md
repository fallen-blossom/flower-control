description: Use Flower to operate local Windows browser pages, accessible app controls, or a selected window through screenshots and keyboard/mouse input.
---

Flower exposes three local MCP servers: flower-web for Brave page elements,
flower-app for Windows accessibility controls, and flower-computer for screenshots
and keyboard/mouse input in a selected window. This is a Windows native Claude
Code preview. It requires the recipient's separately installed Flower helper.

Check flower_status and the corresponding origin probe before first use. A linked
origin is a chat association, not private-profile permission or window selection.
Use the exact tool names discovered in the current session; plugin tools normally
include the plugin and server names. Never manufacture flower_origin or copy a
token from an earlier call. The synchronous Hook supplies it for this attempt.

Prefer Web for DOM actions, App for named accessible controls, and Computer when
the task needs visual coordinates, custom canvas interaction, or keyboard/mouse.
Observe, bind the exact target and revision, act once, and read the new state.
If a result is unknown, check its action_id before retrying. Let deterministic
mechanical steps run without adding an extra model review to every action.

The AI Brave profile is dedicated to agent use. For the user's personal profile,
request Flower's per-chat approval. App and Computer need a selected window.
Claude's normal tool permissions still apply. Ctrl+Alt+9 stops Flower writes;
Stop, pause, and input release are shared with the helper across hosts. Do not
automatically clear Stop, install a new helper, expand the host allowlist, reset
profiles, or upload local data to overcome an error.

Flower adds no telemetry or remote configuration. Jev is optional and can send
approved task data to its service when separately enabled. MCP results enter the
Claude conversation and follow the user's Claude account and privacy settings.
