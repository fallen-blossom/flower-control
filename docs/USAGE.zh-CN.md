# Flower Control 使用说明

[English](USAGE.md)

你可以直接用自然语言描述任务。Codex 会选择 Flower 通道、绑定本地目标、执行动作并读回结果，不需要你在聊天里手动调用每一个 MCP 工具。

## 先选对通道

| 通道 | 优先用于 | 不要拿它做什么 |
| --- | --- | --- |
| **Web** | 表单、页面跳转、文本框、链接、标签页、上传下载、受管登录资料 | 没有配置好的资料，或非 Flower 管理的浏览器会话 |
| **App** | Windows 可访问控件：按钮、菜单、列表、输入框、对话框、设置页 | 只有画布或没有可用控件信息的界面 |
| **Computer** | 指定窗口的视觉布局、拖拽、快捷键、画布和图片按钮 | 全桌面任意控制、密码/UAC 安全桌面、无限快捷键序列 |

目标有可靠控件信息时，先用 Web 或 App。只有真正需要按坐标输入时，才用 Computer。

## 选择目标

### Web

Flower 使用自己管理的 Chromium 内核资料，不会复制你日常浏览器的 Cookie。

- **临时**：公开页面和一次性任务，任务结束后可以回收。
- **AI**：给普通代理任务使用的独立登录资料，会保留数据。
- **个人 / 落花（Luohua）**：单独的个人资料。需要当前聊天明确授权，而且每个浏览器分别授权。

第一次登录时，让 Flower 打开对应资料窗口，你自己完成登录，再正常关闭登录窗口，然后让 Codex 继续。不要让 Computer 代填密码。

### App

尽量说出窗口、应用和要操作的控件。Flower 会绑定目标窗口并核对身份。窗口标题不是永久身份；应用重启或进程变化后要重新选择。

### Computer

日常操作先绑定一个目标窗口，键鼠输入受该目标约束。边框、耗时和 Stop 按钮表示当前 Computer 操作正在进行。另有受遮挡规则约束的桌面概览，它不会顺便授予其他窗口的输入权限。

## 安装后第一次使用

这条路线只用普通窗口和公开网页，不需要管理员名单、工作授权或可选决策服务。

1. **你设置档位**：展开任务栏右下角 **^**，右键花形图标 → **设置**，用左侧实际档位按钮选 **02 普通控制**，等“已保存档位”变为 02。档位立即切换，名单等编辑才用 Ctrl+S。本批候选全新无权限文件时默认 02；已有机器保留原设置。preview.3 原发布快照的旧默认不代表候选已替你切档。
2. **你新建测试文档**：打开记事本，创建空白文档，不使用已有重要文件。
3. **在新的 Codex 聊天发送**：

> 用 Flower 检查三个通道是否可用，告诉我能否开始普通窗口操作，先不要改内容。列出可选的记事本窗口，让我辨认这次新建的空白文档，再绑定它。

4. **在聊天里辨认目标**：Codex 先列窗口，再用候选 ID 绑定；通常不另弹通用窗口选择器。多个记事本时，按列出的标题/进程指出新文档，不必手写 PID 或工具参数。设置里的 Ctrl+Alt+8 是给名单加程序用的，不是这一步。
5. **发送输入任务，亲自看结果**：

> 在刚才绑定的空白记事本里输入“Flower 测试成功”，读回核对。先不保存、不关闭文档。完成后结束本次控制，保留记事本和文字。

你应看到文字，Codex 也应报告实际读回结果。出现人工处理提示，只表示在等你处理，不代表动作完成。

6. **再试公开网页**：

> 用 Flower 临时浏览器打开 https://example.com，读取标题和主标题。完成后只关闭本次临时会话，不动我的其他浏览器窗口。

这句任务表达了普通临时浏览任务的同意，不需要 Luohua 授权，也没有每次必弹的额外 Flower 确认卡。本地档位、真实聊天来源和 Stop 检查仍须通过；网站登录和系统 UAC 由你处理。

7. **以后直接描述目标和成果**。App/Web 有可靠结构时优先用它；画布、拖拽或快捷键才用 Computer。可自己打开计算器，让 Codex 列出并绑定它，只点击一个数字并读回，作为 Computer 小试。

## 完成后与临时离开

可以说：

> 本次任务结束。结束 App 和 Computer 控制、释放按键并关闭控制提示。保留我的应用、未保存文档和成果；只回收本次明确创建且不需要保留的临时浏览器会话，报告是否收尾完成。

Codex 分别用 App/Computer 的 `pause(mode='finish')` 收尾，Web 则清理明确列出的临时会话。这不是一个全局完成按钮。正常结束控制不自动保存或关闭记事本，也不退出托盘助手；下次任务仍可使用助手。你自己决定保存或放弃测试文档，关掉聊天本身不算已核验收尾。

离开时想挡住全部新操作，可用独立的**紧急停止全部 Flower / Ctrl+Alt+Shift+9**，或在设置中切 **01 完全停止**；只暂停 Computer 则用托盘暂停入口。恢复方法见[权限与设置](PERMISSIONS.zh-CN.md)，个人资料撤销见[浏览器说明](BROWSER_PROFILES.zh-CN.md#撤销个人资料授权)。

## 第一次可以这样问

只读状态：

> 检查 Flower 的 Web、App、Computer 三个 status。对比 loaded source 和 on-disk source，显示当前 Stop 和暂停状态。先不要操作目标。

Web 临时页：

> 用临时 Flower 浏览器打开一个公开页面，读取标题和可见主标题，然后关闭临时会话。

App 无害小试：

> 用 Flower App 操作我选择的记事本窗口，读取标题和一个控件。不要保存文件。

Computer 有限小试：

> 用 Flower Computer 操作我选择的计算器窗口，点击一个可见数字并读回结果。只做这一步，然后停止。

不要从密码、验证码、支付、私人资料或重要未保存文档开始。

## 权限、目标检查和 Stop

每次真实动作前，Flower 都会重新检查当前档位、目标身份、黑名单、来源状态、Stop 和暂停状态。后面动作还会再查，一次成功点击不是永久授权。

| 控制 | 效果 |
| --- | --- |
| **01 完全停止** | Web、App、Computer 全部停止派发，托盘和设置仍可用 |
| **Ctrl+Alt+Shift+9 / 紧急停止全部 Flower** | 全通道 Stop，阻止后续写入；注册失败时看诊断，明确本地继续才恢复 |
| **Ctrl+Alt+9** | 结束当前 Computer 输入并释放按键；不改变已保存档位，也不创建全局 Stop |
| **HUD Stop** | 结束当前 Computer 周期并释放按键 |
| **托盘“停止 Computer Use”** | 结束当前 Computer 操作；App 和 Web 不会从这次 Stop 自动得到新授权 |
| **Computer 暂停** | 拒绝新的 Computer 输入，App 和 Web 可以继续 |
| **恢复** | 重新检查后只恢复当前代次，不重放上一次动作 |

目标变了、窗口关了、源码探针失败、助手断线或结果未知时，先停下重新观察。不要让代理对破坏性或结果未知的输入“直接再试一次”。

## 管理员窗口和管理员启动

- 管理员窗口已经打开，需要读取或操作时，用 03。
- 已经为精确程序配置好启动名单或工作授权后，才考虑 04。
- 启动器拉起的子程序、关联程序或后来换掉的 exe 不继承之前的批准。
- UAC 安全桌面、密码输入和旧系统接管路线在本预览版中已冻结。

对某个任务的批准不会变成对无关窗口和后续任务的通配授权。

## 隐私和数据

Flower 自身不加入遥测、崩溃上传、远端配置或自动更新。目标网站/应用、Codex 的模型服务和可选的决策服务各有自己的联网与数据处理规则。

不要把凭据、Cookie、登录文件或私人截图放进聊天、命令行、issue 或发布包。密钥只在本机设置中输入。可选服务默认关闭，启用前先检查接收方和发送内容。

## 中断后的正确问法

> 报告当前 Flower status 和最后一次目标身份。不要重复动作。告诉我结果是已确认、未知、已停止还是被拒绝。

然后决定重新选目标、重新观察后恢复、降低档位，还是保持停止。安全默认是保留现有拒绝和 Stop 状态。
