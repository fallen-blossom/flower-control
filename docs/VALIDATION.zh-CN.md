# Flower Control 0.1.0 验证说明

[English](VALIDATION.md)

**最终 0.1.0 安装器尚未完成真实安装/控制验收，也尚未发布。** 下列检查对应当前源码或已核实的编码器字节，不把它们写成未发布整包已通过。

## 已完成的检查

| 范围 | 证据与适用边界 |
| --- | --- |
| Windows 版本信息 | Native helper、App worker、WGC worker、signer probe、Setup 已实际构建并检查 PE/程序集版本：产品 0.1.0，文件/程序集 0.1.0.0。证明编译和元数据，不证明 High/UAC 操作。 |
| 安装与本机状态 | 源码/隔离检查覆盖根发现、原计划绑定、本机入口准入、Stop 保留、普通偏好草稿、空间审阅及受控个人资料回收。夹具不代表真实用户安装或前台任务。 |
| 发行材料绑定 | 构建前与归档前核对固定编码器、许可、NOTICE、源码 ZIP、输入 lock 和配方；公共源码导出包含八个编码器构建文件。 |
| 最小录屏编码器 | 已核实的 FFmpeg 8.1.1-flower-minimal-1 字节在 System32-only PATH 下运行。三份完整源码档对应构建记录中的全部 10,633 个文件，保留原组件/运行时声明。短合成帧用生产编码/时间线参数，与原准入编码器比对四个 PTS、解码、补齐尺寸及 progress 完成。 |

编码器夹具没有验证输出大小上限或真实截图。两版的 MP4 容器时长都与末帧显示时间戳有差异；比较依据是时间戳与解码结果，不宣称容器时长严格等于请求。源码/构建清单支持追溯，不等于独立重编或完整法律合规结论。

## 最终安装器尚未验证的部分

- 用最终 0.1.0 包实际首装、取消/恢复、升级/同版本维护和卸载，以及另一套干净、离线 Windows 环境中的完整过程。
- 真实普通/High 操作、UAC 交接、宿主启用与 Hook 信任、新聊天加载，以及对应包的 Web/App/Computer 完整任务。
- 真实前台录屏与输入、全部 Stop 按钮/热键、拖放成果，以及焦点/DPI/多显示器/锁屏/休眠的组合路径。

文件核验、进程退出成功和 status 握手各自只能证明对应阶段。[安装器指南](INSTALLER.zh-CN.md)说明需要你确认的结果。人类发行版本与已安装运行时的内容指纹分开记录。

## 历史任务证据

先前 Codex 安装基线完成过表格、文档、绘图、公开网页、文件交接、所属弹窗和可选 Jev 检查。文档着色题未达到精度要求；自然重叠的前台争用没有实际形成。这些结果保留原安装版本范围；详细记录见[preview.3 验证快照](https://github.com/fallen-blossom/flower-control/blob/00632f9f186609ccee4334a84dd44b237f6c372e/docs/VALIDATION.zh-CN.md)，不作为最终 0.1.0 验收或排行榜复现。

## 发行身份与反馈

0.1.0 采用未签名方式（`signed: false`）。通过官方 GitHub 文件、匹配源码/依赖构建输入与 SHA-256 核对字节身份，不提供公信发布者签名。安全缺陷可用已启用的[私密漏洞报告](https://github.com/fallen-blossom/flower-control/security/advisories/new)；普通故障按[排障说明](TROUBLESHOOTING.zh-CN.md)提供实际版本、状态、错误与最小复现，不附私人资料。
