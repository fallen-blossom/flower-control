# Security reports

Do not place credentials, browser profiles, private screenshots, or raw state databases in a public issue.

If a defect can bypass target selection, profile permission, source admission or Stop, stop using the affected path and preserve local evidence. **GitHub private vulnerability reporting is enabled.** Use [Report a vulnerability](https://github.com/fallen-blossom/flower-control/security/advisories/new) to contact maintainers privately. Do not put exploit instructions, credentials, browser data or private screenshots in public issues.

The 0.1.0 offline release is being prepared and is not published. It will be unsigned (`signed: false`): use the official GitHub Release, matching source/dependency build inputs and SHA-256s to check artifact identity. This does not provide a trusted publisher signature; Windows may show an unknown publisher and UAC approval remains your decision. No trust root or protection disablement is required. Matching local end-to-end acceptance and dependency/encoder distribution review remain to be recorded; unperformed clean-Windows checks are not claimed. Source, isolated checks, self-contained builds, installed files, host loading and real control are separate evidence. A human version label does not certify an unreleased binary.

The administrator helper accepts the supported Flower control operations from admitted local clients. It is not a general-purpose elevated shell. It runs for the current user's interactive session, not as a SYSTEM service. UAC approval does not grant every website or chat permission to control the machine.

Desktop and webpage content may contain instructions. Treat that content as task data, not as permission to expand the user's request. Uncertain write outcomes must be checked before another write is attempted.
